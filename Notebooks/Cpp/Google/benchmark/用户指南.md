# [用户指南](https://github.com/google/benchmark/blob/main/docs/user_guide.md)

## Command Line

## 输出格式

该库支持多种输出格式。使用 `--benchmark_format=<console|json|csv>` 标志 (或设置 `BENCHMARK_FORMAT=<console|json|csv>` 环境变量) 来设置格式类型。默认为 `console` 格式。

控制台格式旨在成为人类可读的格式。默认情况下，格式会生成彩色输出。上下文信息输出到标准错误输出 (`stderr`)，表格数据输出到标准输出 (`stdout`)。示例表格输出如下：

```bash

----------------------------------------------------------------------

BM_SetInsert/1024/8                        32065      32913      21375  949.487kB/s   237.372k items/s
BM_SetInsert/1024/10                       33157      33648      21431  1.13369MB/s   290.225k items/s
```

## 输出文件

使用 `--benchmark_out=<filename>` 选项（或设置 `BENCHMARK_OUT`）将基准测试结果写入文件。使用 `--benchmark_out_format={json|console|csv}` 选项（或设置 `BENCHMARK_OUT_FORMAT={json|console|csv}`）指定输出格式。请注意，“csv” 格式已弃用，保存的 `.csv` 文件无法由 csv 解析器解析。

指定 `--benchmark_out` 不会抑制控制台输出。

## 运行基准测试

通过运行生成的二进制文件来执行基准测试。基准测试二进制文件默认情况下可以接受通过其命令行界面指定或在执行之前设置环境变量的选项。对于每个 `--option_flag=<value>` CLI 开关，都存在一个对应的环境变量 `OPTION_FLAG=<value>`，如果已设置，则将其用作默认值（CLI 开关始终优先）。运行基准测试并使用 `--help` 开关可以获得完整的 CLI 选项列表。

## 运行基准测试子集

可以使用 `--benchmark_filter=<regex>` 选项（或 `BENCHMARK_FILTER=<regex>` 环境变量）来仅运行匹配指定 `<regex>` 的基准测试。例如：

```bash
$ ./run_benchmarks.x --benchmark_filter=BM_memcpy/32
Run on (1 X 2300 MHz CPU )
2016-06-25 19:34:24
Benchmark              Time           CPU Iterations
----------------------------------------------------
BM_memcpy/32          11 ns         11 ns   79545455
BM_memcpy/32k       2181 ns       2185 ns     324074
BM_memcpy/32          12 ns         12 ns   54687500
BM_memcpy/32k       1834 ns       1837 ns     357143
```

## 禁用基准测试

可以通过将基准测试函数重命名为带有前缀 `DISABLED_` 来临时禁用基准测试。这将导致基准测试在运行时被跳过。

## 结果比较

可以比较基准测试结果。请参阅[附加工具文档](https://github.com/google/benchmark/blob/main/docs/tools.md)

## 额外上下文

有时在结果之前打印的内容中添加额外的上下文会很有用。默认情况下，此部分包含有关运行基准测试的 CPU 的信息。如果您想添加更多上下文，可以使用 `benchmark_context` 命令行标志：

```bash
$ ./run_benchmarks --benchmark_context=pwd=`pwd`
Run on (1 x 2300 MHz CPU)
pwd: /home/user/benchmark/
Benchmark              Time           CPU Iterations
----------------------------------------------------
BM_memcpy/32          11 ns         11 ns   79545455
BM_memcpy/32k       2181 ns       2185 ns     324074
```

使用 API 也可获得相同结果：

```c++
  benchmark::AddCustomContext("foo", "bar");
```

注意，尝试使用相同的键添加第二个值将失败并显示错误信息。

## 运行时和报告注意事项

当执行基准测试二进制文件时，每个基准测试函数都会按顺序运行。运行的迭代次数是通过多次运行基准测试并测量所花费的时间以及确保最终结果在统计上稳定来动态确定的。因此，运行速度更快的基准测试函数将比运行速度更慢的基准测试函数运行更多次迭代，并且会报告迭代次数。

### 最小时间

在所有情况下，基准测试运行的迭代次数都由基准测试所花费的时间决定。具体来说，迭代次数至少为 1，不超过 1e9，直到 CPU 时间大于最小时间，或者墙上时钟时间为最小时间的 5 倍。最小时间是通过对注册的基准测试对象调用 `MinTime` 来为每个基准测试设置的。

### 预热运行

此外，为了获得稳定的结果，可能需要预热基准测试，因为例如基准测试代码的缓存效应。预热意味着在实际考虑结果之前运行基准测试一段时间。预热运行的时间可以通过对注册的基准测试对象调用 `MinWarmUpTime` 或使用 `--benchmark_min_warmup_time` 命令行选项来设置每个基准测试。请注意，对于单个基准测试，`MinWarmUpTime` 将覆盖 `--benchmark_min_warmup_time` 的值。每个基准测试的预热运行需要多少次迭代，其确定方式与上面段落中描述的相同。默认情况下，预热阶段设置为 0 秒，因此被禁用。

### 重复运行

然后报告每个迭代运行的平均计时。如果使用 `--benchmark_repetitions` 命令行选项或在注册时请求多次重复，则基准测试函数将运行多次，并且还会报告这些重复的统计结果。

报告中除了每个基准测试的条目之外，前言还将包含有关运行基准测试的机器的信息。

## 设置/清理

可以使用回调传递给 Setup/Teardown 来完成特定于每个基准测试的全局设置/清理：

设置/清理回调将针对每个基准测试调用一次。如果基准测试是多线程的（将在 k 个线程中运行），它们将在每次使用 k 个线程运行之前调用一次。

如果基准测试使用不同的线程大小组，则上述情况对每个大小组都成立。

例如：

```c++
static void DoSetup(const benchmark::State& state) {
}

static void DoTeardown(const benchmark::State& state) {
}

static void BM_func(benchmark::State& state) {...}

BENCHMARK(BM_func)->Arg(1)->Arg(3)->Threads(16)->Threads(32)->Setup(DoSetup)->Teardown(DoTeardown);

```

在这个例子中，`DoSetup` 和 `DoTeardown` 将分别被调用 4 次，具体来说，每个系列调用一次：

- BM_func_Arg_1_Threads_16, BM_func_Arg_1_Threads_32 
- BM_func_Arg_3_Threads_16, BM_func_Arg_3_Threads_32

## 传递参数

有时可以使用只接受一个额外的参数来指定要运行的系列中哪一个的例程来实现一系列基准测试。例如，以下代码定义了一系列基准测试，用于测量不同长度的 `memcpy()` 调用的速度：

```c++
static void BM_memcpy(benchmark::State& state) {
  char* src = new char[state.range(0)];
  char* dst = new char[state.range(0)];
  memset(src, 'x', state.range(0));
  for (auto _ : state)
    memcpy(dst, src, state.range(0));
  state.SetBytesProcessed(int64_t(state.iterations()) *
                          int64_t(state.range(0)));
  delete[] src;
  delete[] dst;
}
BENCHMARK(BM_memcpy)->Arg(8)->Arg(64)->Arg(512)->Arg(4<<10)->Arg(8<<10);
```

前面的代码相当重复，可以用以下简写形式替换。以下调用将在指定范围内选择一些合适的参数，并为每个参数生成基准测试。

```c++
BENCHMARK(BM_memcpy)->Range(8, 8<<10);
```

默认情况下，范围内的参数以 8 的倍数生成，上面的命令选择 [8, 64, 512, 4k, 8k]。在以下代码中，范围乘数改为 2 的倍数。

```c++
BENCHMARK(BM_memcpy)->RangeMultiplier(2)->Range(8, 8<<10);
```

现在生成的参数是 [8, 16, 32, 64, 128, 256, 512, 1024, 2k, 4k, 8k]。

上段代码展示了一种定义稀疏范围的方法。以下示例展示了一种定义密集范围的方法。然后用于基准测试随着大小均匀递增的 `std::vector` 初始化性能。

```c++
static void BM_DenseRange(benchmark::State& state) {
  for(auto _ : state) {
    std::vector<int> v(state.range(0), state.range(0));
    auto data = v.data();
    benchmark::DoNotOptimize(data);
    benchmark::ClobberMemory();
  }
}
BENCHMARK(BM_DenseRange)->DenseRange(0, 1024, 128);
```

现在生成的参数是 [0, 128, 256, 384, 512, 640, 768, 896, 1024]。

您可能拥有依赖两个或多个输入的基准测试。例如，以下代码定义了一系列用于测量集合插入速度的基准测试。

```c++
static void BM_SetInsert(benchmark::State& state) {
  std::set<int> data;
  for (auto _ : state) {
    state.PauseTiming();
    data = ConstructRandomSet(state.range(0));
    state.ResumeTiming();
    for (int j = 0; j < state.range(1); ++j)
      data.insert(RandomNumber());
  }
}
BENCHMARK(BM_SetInsert)
    ->Args({1<<10, 128})
    ->Args({2<<10, 128})
    ->Args({4<<10, 128})
    ->Args({8<<10, 128})
    ->Args({1<<10, 512})
    ->Args({2<<10, 512})
    ->Args({4<<10, 512})
    ->Args({8<<10, 512});
```

之前冗长的代码可以用以下简写形式替换。以下宏将从两个指定范围的乘积中挑选几个合适的参数，并为每个这样的参数对生成一个基准测试。

```c++
BENCHMARK(BM_SetInsert)->Ranges({{1<<10, 8<<10}, {128, 512}});
```

某些基准测试可能需要无法使用 `Ranges` 表示的特定参数值。在这种情况下，`ArgsProduct` 提供了为提供的向量乘积中的每个组合生成基准测试输入的功能。

```c++
BENCHMARK(BM_SetInsert)
    ->ArgsProduct({{1<<10, 3<<10, 8<<10}, {20, 40, 60, 80}})
// would generate the same benchmark arguments as
BENCHMARK(BM_SetInsert)
    ->Args({1<<10, 20})
    ->Args({3<<10, 20})
    ->Args({8<<10, 20})
    ->Args({3<<10, 40})
    ->Args({8<<10, 40})
    ->Args({1<<10, 40})
    ->Args({1<<10, 60})
    ->Args({3<<10, 60})
    ->Args({8<<10, 60})
    ->Args({1<<10, 80})
    ->Args({3<<10, 80})
    ->Args({8<<10, 80});
```

对于最常见的场景，提供了用于为给定的稀疏或密集范围创建整数列表的帮助器方法。

```c++
BENCHMARK(BM_SetInsert)
    ->ArgsProduct({
      benchmark::CreateRange(8, 128, /*multi=*/2),
      benchmark::CreateDenseRange(1, 4, /*step=*/1)
    })
// would generate the same benchmark arguments as
BENCHMARK(BM_SetInsert)
    ->ArgsProduct({
      {8, 16, 32, 64, 128},
      {1, 2, 3, 4}
    });
```

对于更复杂的输入模式，将自定义函数传递给 `Apply` 允许以编程方式指定运行基准测试的一组任意参数。以下示例枚举一个参数上的密集范围，另一个参数上的稀疏范围。

```c++
static void CustomArguments(benchmark::internal::Benchmark* b) {
  for (int i = 0; i <= 10; ++i)
    for (int j = 32; j <= 1024*1024; j *= 8)
      b->Args({i, j});
}
BENCHMARK(BM_SetInsert)->Apply(CustomArguments);
```

### 向基准测试传递任意参数

在 C++11 中，可以定义一个接受任意数量额外参数的基准测试。`BENCHMARK_CAPTURE(func, test_case_name, ...args)` 宏创建一个基准测试，它调用 `func`，其中 `benchmark::State` 为第一个参数，后面跟着指定的 `args...`。`test_case_name` 会附加到基准测试的名称后面，应该描述传递的值。

```c++
template <class ...Args>
void BM_takes_args(benchmark::State& state, Args&&... args) {
  auto args_tuple = std::make_tuple(std::move(args)...);
  for (auto _ : state) {
    std::cout << std::get<0>(args_tuple) << ": " << std::get<1>(args_tuple)
              << '\n';
    [...]
  }
}
// Registers a benchmark named "BM_takes_args/int_string_test" that passes
// the specified values to `args`.
BENCHMARK_CAPTURE(BM_takes_args, int_string_test, 42, std::string("abc"));

// Registers the same benchmark "BM_takes_args/int_test" that passes
// the specified values to `args`.
BENCHMARK_CAPTURE(BM_takes_args, int_test, 42, 43);
```

请注意，`...args` 的元素可能引用全局变量。用户应该避免在基准测试内部修改全局状态。

## 计算渐近复杂度 (Big O)

可以计算一系列基准测试的渐近复杂度。以下代码将计算字符串比较运行时间的高阶项系数和归一化均方根误差。

```c++
static void BM_StringCompare(benchmark::State& state) {
  std::string s1(state.range(0), '-');
  std::string s2(state.range(0), '-');
  for (auto _ : state) {
    auto comparison_result = s1.compare(s2);
    benchmark::DoNotOptimize(comparison_result);
  }
  state.SetComplexityN(state.range(0));
}
BENCHMARK(BM_StringCompare)->RangeMultiplier(2)->Range(1<<10, 1<<18)->Complexity(benchmark::oN);
```

如下面的调用所示，渐近复杂度也可能自动计算。

```c++
BENCHMARK(BM_StringCompare)->RangeMultiplier(2)->Range(1<<10, 1<<18)->Complexity();
```

以下代码将使用 lambda 函数指定渐近复杂度，该函数可能用于自定义高阶项计算。

```c++
BENCHMARK(BM_StringCompare)->RangeMultiplier(2)
    ->Range(1<<10, 1<<18)->Complexity([](benchmark::IterationCount n)->double{return n; });
```

您可以通过以下方式更改基准测试的名称：

BENCHMARK(BM_memcpy)->Name("memcpy")->RangeMultiplier(2)->Range(8, 8<<10);

## 模板基准测试

此示例生成并消耗大小为 `sizeof(v)` 的消息 `range_x` 次。它还输出没有多路编程时的吞吐量。

```c++
template <class Q> void BM_Sequential(benchmark::State& state) {
  Q q;
  typename Q::value_type v;
  for (auto _ : state) {
    for (int i = state.range(0); i--; )
      q.push(v);
    for (int e = state.range(0); e--; )
      q.Wait(&v);
  }
  // actually messages, not bytes:
  state.SetBytesProcessed(
      static_cast<int64_t>(state.iterations())*state.range(0));
}
// C++03
BENCHMARK_TEMPLATE(BM_Sequential, WaitQueue<int>)->Range(1<<0, 1<<10);

// C++11 or newer, you can use the BENCHMARK macro with template parameters:
BENCHMARK(BM_Sequential<WaitQueue<int>>)->Range(1<<0, 1<<10);

```

提供了三个宏来添加基准测试模板。

```c++
#ifdef BENCHMARK_HAS_CXX11
#define BENCHMARK(func<...>) // Takes any number of parameters.
#else // C++ < C++11
#define BENCHMARK_TEMPLATE(func, arg1)
#endif
#define BENCHMARK_TEMPLATE1(func, arg1)
#define BENCHMARK_TEMPLATE2(func, arg1, arg2)
```

## 带参数的模板基准测试

有时需要对基准测试进行模板化，并向其提供参数。

```c++
template <class Q> void BM_Sequential_With_Step(benchmark::State& state, int step) {
  Q q;
  typename Q::value_type v;
  for (auto _ : state) {
    for (int i = state.range(0); i-=step; )
      q.push(v);
    for (int e = state.range(0); e-=step; )
      q.Wait(&v);
  }
  // actually messages, not bytes:
  state.SetBytesProcessed(
      static_cast<int64_t>(state.iterations())*state.range(0));
}

BENCHMARK_TEMPLATE1_CAPTURE(BM_Sequential, WaitQueue<int>, Step1, 1)->Range(1<<0, 1<<10);
```

## 夹具

夹具 (fixture) 测试通过首先定义一个派生自 `::benchmark::Fixture` 的类型，然后使用以下宏创建/注册测试：

- `BENCHMARK_F(ClassName, Method)`
- `BENCHMARK_DEFINE_F(ClassName, Method)`
- `BENCHMARK_REGISTER_F(ClassName, Method)`

例如：

```c++
class MyFixture : public benchmark::Fixture {
public:
  void SetUp(::benchmark::State& state) {
  }

  void TearDown(::benchmark::State& state) {
  }
};

BENCHMARK_F(MyFixture, FooTest)(benchmark::State& st) {
   for (auto _ : st) {
     ...
  }
}

BENCHMARK_DEFINE_F(MyFixture, BarTest)(benchmark::State& st) {
   for (auto _ : st) {
     ...
  }
}
/* BarTest is NOT registered */
BENCHMARK_REGISTER_F(MyFixture, BarTest)->Threads(2);
/* BarTest is now registered */
```

## 模板夹具

您还可以使用以下宏创建模板夹具：

- `BENCHMARK_TEMPLATE_F(ClassName, Method, ...)`
- `BENCHMARK_TEMPLATE_DEFINE_F(ClassName, Method, ...)`

例如：

```c++
template<typename T>
class MyFixture : public benchmark::Fixture {};

BENCHMARK_TEMPLATE_F(MyFixture, IntTest, int)(benchmark::State& st) {
   for (auto _ : st) {
     ...
  }
}

BENCHMARK_TEMPLATE_DEFINE_F(MyFixture, DoubleTest, double)(benchmark::State& st) {
   for (auto _ : st) {
     ...
  }
}

BENCHMARK_REGISTER_F(MyFixture, DoubleTest)->Threads(2);
```

## 自定义计数器

您可以添加具有用户定义名称的自定义计数器。以下示例将在其输出中添加列 "Foo"、"Bar" 和 "Baz":

```c++
static void UserCountersExample1(benchmark::State& state) {
  double numFoos = 0, numBars = 0, numBazs = 0;
  for (auto _ : state) {
    // ... count Foo,Bar,Baz events
  }
  state.counters["Foo"] = numFoos;
  state.counters["Bar"] = numBars;
  state.counters["Baz"] = numBazs;
}
```

`state.counters` 对象是一个带有 `std::string` 键和 `Counter` 值的 `std::map`。后者类似于双精度类，通过隐式转换为 `double&`。因此，您可以使用所有标准算术赋值运算符 (=,+=,-=,*=,/=) 来更改每个计数器的值。

在多线程基准测试中，每个计数器仅在线程调用时设置。基准测试完成后，将对来自每个线程的计数器进行求和；结果总和将是基准测试显示的值。

`Counter` 构造函数接受三个参数：值作为 `double`；一个位标志，允许您将计数器显示为速率，和/或作为每个线程迭代，和/或作为每个线程平均值，和/或迭代不变性，和/或最终反转结果；以及指定“单位”的标志 - 即 1k 是 1000（默认，`benchmark::Counter::OneK::kIs1000`）还是 1024（`benchmark::Counter::OneK::kIs1024`）？

```c++
  // 设置一个简单的计数器
  state.counters["Foo"] = numFoos;

  // 将计数器设置为速率。 它将除以基准测试的持续时间来呈现。
  // 意思是：每秒处理多少个 'foo'？
  state.counters["FooRate"] = Counter(numFoos, benchmark::Counter::kIsRate);

  // 将计数器设置为速率。 它将除以基准测试的持续时间来呈现，并反转结果。
  // 意思是：处理一个 'foo' 需要多少秒？
  state.counters["FooInvRate"] = Counter(numFoos, benchmark::Counter::kIsRate | benchmark::Counter::kInvert);

  // 将计数器设置为线程平均值。 它将除以线程数来呈现。
  state.counters["FooAvg"] = Counter(numFoos, benchmark::Counter::kAvgThreads);

  // 还有一个组合标志：
  state.counters["FooAvgRate"] = Counter(numFoos,benchmark::Counter::kAvgThreadsRate);

  // 这表示我们每次迭代以 state.range(0) 字节的速率进行处理：
  state.counters["BytesProcessed"] = Counter(state.range(0), benchmark::Counter::kIsIterationInvariantRate, benchmark::Counter::OneK::kIs1024);
```

当您在 C++11 模式或更高版本中编译时，可以使用 `insert()` 和 `std::initializer_list`：

```c++
  // With C++11, this can be done:
  state.counters.insert({{"Foo", numFoos}, {"Bar", numBars}, {"Baz", numBazs}});
  // ... instead of:
  state.counters["Foo"] = numFoos;
  state.counters["Bar"] = numBars;
  state.counters["Baz"] = numBazs;
```

## 多线程基准测试

在多线程测试（基准测试由多个线程同时调用）中，可以保证任何线程都不会在所有线程都到达基准测试循环的开始之前启动，并且所有线程都将在任何线程退出基准测试循环之前完成。（这种行为也由 `KeepRunning()` API 提供）因此，任何全局设置或清理都可以包装在针对线程索引的检查中：

```c++
static void BM_MultiThreaded(benchmark::State& state) {
  if (state.thread_index() == 0) {
    // Setup code here.
  }
  for (auto _ : state) {
    // Run the test as normal.
  }
  if (state.thread_index() == 0) {
    // Teardown code here.
  }
}
BENCHMARK(BM_MultiThreaded)->Threads(2);
```

要跨越一系列线程计数运行基准测试，请改用 `ThreadRange` 代替 `Threads`。它接受两个参数（`min_threads` 和 `max_threads`），并针对包含范围中的值运行基准测试一次。例如：

```c++
BENCHMARK(BM_MultiThreaded)->ThreadRange(1, 8);
```

将使用线程数 1、2、4 和 8 运行 `BM_MultiThreaded`。

如果基准测试代码本身使用线程，并且您想要将其与单线程代码进行比较，则您可能希望使用实时的（“wallclock”）测量进行延迟比较：

```c++
BENCHMARK(BM_test)->Range(8, 8<<10)->UseRealTime();
```

如果没有 `UseRealTime`，则默认使用 CPU 时间。

## CPU 计时器

默认情况下，CPU 计时器只会测量主线程花费的时间。如果基准测试本身内部使用线程，那么此测量可能不是您想要的。相反，有一种方法可以测量进程的所有线程的总 CPU 使用率。

```C++
void callee(int i);

static void MyMain(int size) {
#pragma omp parallel for
  for(int i = 0; i < size; i++)
    callee(i);
}

static void BM_OpenMP(benchmark::State& state) {
  for (auto _ : state)
    MyMain(state.range(0));
}

// 测量主线程花费的时间，用它来决定运行基准测试循环多长时间。 
// 取决于内部实现细节，可以测量从接近零（工作移交至工作线程之前/之后的花费）到整个单线程时间的所有内容。
BENCHMARK(BM_OpenMP)->Range(8, 8<<10);

// 测量用户可见时间，墙上时钟（从字面上看，即墙上时钟上过去的时间），用它来决定运行基准测试循环多长时间。 
// 这将始终有意义，并且在单线程情况下将与主线程花费的时间相匹配，通常会随着执行工作的内部线程数量而减少。
BENCHMARK(BM_OpenMP)->Range(8, 8<<10)->UseRealTime();

// 测量总 CPU 消耗，用它来决定运行基准测试循环多长时间。 这将始终测量到不少于单线程情况下主线程花费的时间。
BENCHMARK(BM_OpenMP)->Range(8, 8<<10)->MeasureProcessCPUTime();

// 最后两个的混合。 测量总 CPU 消耗，但使用墙上时钟来决定运行基准测试循环多长时间。
BENCHMARK(BM_OpenMP)->Range(8, 8<<10)->MeasureProcessCPUTime()->UseRealTime();
```

## 控制计时器

通常，整个工作循环的持续时间（`for (auto _ : state) {}`）都会被测量。但有时，需要在该循环内每迭代执行一些工作，但不将该时间计入基准测试时间。这是可能的，尽管不推荐这样做，因为它开销很大。

```c++
static void BM_SetInsert_With_Timer_Control(benchmark::State& state) {
  std::set<int> data;
  for (auto _ : state) {
    state.PauseTiming(); // Stop timers. They will not count until they are resumed.
    data = ConstructRandomSet(state.range(0)); // Do something that should not be measured
    state.ResumeTiming(); // And resume timers. They are now counting again.
    // The rest will be measured.
    for (int j = 0; j < state.range(1); ++j)
      data.insert(RandomNumber());
  }
}
BENCHMARK(BM_SetInsert_With_Timer_Control)->Ranges({{1<<10, 8<<10}, {128, 512}});
```

## 手动计时

当 CPU 时间或真实时间都无法用于准确测量性能时，可以使用完全手动计时功能。 该功能通过 `UseManualTime` 函数启用。

当使用 `UseManualTime` 时，基准测试代码必须在基准测试循环的每次迭代中调用 `SetIterationTime` 一次，以报告手动测量的运行时间。

例如，对于 GPU 执行（例如 OpenCL 或 CUDA 内核、OpenGL 或 Vulkan 或 Direct3D 绘制调用）的基准测试，使用 CPU 时间或真实时间无法进行准确的测量。相反，可以使用专用的 API 进行准确的测量，并将这些测量结果通过 `SetIterationTime` 函数报告回去。

```c++
static void BM_ManualTiming(benchmark::State& state) {
  int microseconds = state.range(0);
  std::chrono::duration<double, std::micro> sleep_duration {
    static_cast<double>(microseconds)
  };

  for (auto _ : state) {
    auto start = std::chrono::high_resolution_clock::now();
    // Simulate some useful workload with a sleep
    std::this_thread::sleep_for(sleep_duration);
    auto end = std::chrono::high_resolution_clock::now();

    auto elapsed_seconds =
      std::chrono::duration_cast<std::chrono::duration<double>>(
        end - start);

    state.SetIterationTime(elapsed_seconds.count());
  }
}
BENCHMARK(BM_ManualTiming)->Range(1, 1<<17)->UseManualTime();
```

## 设置时间单位

如果基准测试运行几毫秒，则由于默认输出数据单位为纳秒，因此可能难以直观地比较测量时间。为了手动设置时间单位，可以手动指定：

```c++
BENCHMARK(BM_test)->Unit(benchmark::kMillisecond);
```

此外，还可以使用 `--benchmark_time_unit={ns|us|ms|s}` 命令行参数全局设置默认时间单位。该参数仅影响未显式设置时间单位的基准测试。

## 防止优化

为了防止编译器优化掉某个值或表达式，可以使用 `benchmark::DoNotOptimize(...)` 和 `benchmark::ClobberMemory()` 函数。

```c++
static void BM_test(benchmark::State& state) {
  for (auto _ : state) {
      int x = 0;
      for (int i=0; i < 64; ++i) {
        benchmark::DoNotOptimize(x += i);
      }
  }
}
```

`DoNotOptimize(<expr>)` 强制将 `<expr>` 的结果存储在内存或寄存器中。对于基于 GNU 的编译器，它用作全局内存的读/写屏障。更具体地说是，它强制编译器刷新挂起的写入到内存并根据需要重新加载任何其他值。

请注意，`DoNotOptimize(<expr>)` 不会以任何方式阻止对 `<expr>` 的优化。当结果已经知道时，甚至可以完全删除 `<expr>`。

```c++
  /* Example 1: `<expr>` is removed entirely. */
  int foo(int x) { return x + 42; }
  while (...) DoNotOptimize(foo(0)); // Optimized to DoNotOptimize(42);

  /*  Example 2: Result of '<expr>' is only reused */
  int bar(int) __attribute__((const));
  while (...) DoNotOptimize(bar(0)); // Optimized to:
  // int __result__ = bar(0);
  // while (...) DoNotOptimize(__result__);
```

防止优化的第二个工具是 `ClobberMemory()` 函数。简而言之，`ClobberMemory()` 强制编译器执行所有挂起的写入操作到全局内存。由块作用域对象管理的内存必须在被覆盖之前使用 `DoNotOptimize(...)` 进行 "转义"。 在下面的例子中，`ClobberMemory()` 防止了对 `v.push_back(42)` 的调用被优化掉。

```c++
static void BM_vector_push_back(benchmark::State& state) {
  for (auto _ : state) {
    std::vector<int> v;
    v.reserve(1);
    auto data = v.data();           // Allow v.data() to be clobbered. Pass as non-const
    benchmark::DoNotOptimize(data); // lvalue to avoid undesired compiler optimizations
    v.push_back(42);
    benchmark::ClobberMemory(); // Force 42 to be written to memory.
  }
}
```

注意 `ClobberMemory()` 仅适用于基于 GNU 或 MSVC 的编译器。

## 统计：报告重复基准测试的平均值、中位数、标准差和变异系数

默认情况下，每个基准测试只运行一次并报告单个结果。然而，基准测试通常会存在噪声，单个结果可能无法代表整体性能。因此，可以重复运行基准测试。

运行每个基准测试的次数可以通过 `--benchmark_repetitions` 标志全局指定，也可以通过对已注册的基准测试对象调用 `Repetitions` 函数逐个指定。当基准测试运行多次时，将报告运行结果的平均值、中位数、标准差和变异系数。

此外，还可以使用 `--benchmark_report_aggregates_only={true|false}`、`--benchmark_display_aggregates_only={true|false}` 标志或 `ReportAggregatesOnly(bool)`、`DisplayAggregatesOnly(bool)` 函数来更改重复测试的报告方式。默认情况下，会报告每个重复运行的结果。当 `report aggregates only` 选项为 `true` 时，只报告运行结果的汇总统计量（即平均值、中位数、标准差和变异系数，如果请求了复杂度测量，也可能会包括这些测量）到报告器（标准输出（控制台）和文件）。但是，当只有 `display aggregates only` 选项为 `true` 时，标准输出中只显示汇总统计量，而文件输出仍然包含所有内容。对已注册的基准测试对象调用 `ReportAggregatesOnly(bool)` 或 `DisplayAggregatesOnly(bool)` 会覆盖相应标志的值。

## 自定义统计信息

虽然这些汇总统计量很有用，但对于某些场景可能还不够。例如，您可能想知道最大观测值是多少，因为您有一些实时限制。实现这个功能很简单。以下代码将通过 lambda 函数定义一个要计算的自定义统计量。

```c++
void BM_spin_empty(benchmark::State& state) {
  for (auto _ : state) {
    for (int x = 0; x < state.range(0); ++x) {
      benchmark::DoNotOptimize(x);
    }
  }
}

BENCHMARK(BM_spin_empty)
  ->ComputeStatistics("max", [](const std::vector<double>& v) -> double {
    return *(std::max_element(std::begin(v), std::end(v)));
  })
  ->Arg(512);
```

虽然统计数据通常以时间单位生成值，但你也可以生成百分比:

```c++
void BM_spin_empty(benchmark::State& state) {
  for (auto _ : state) {
    for (int x = 0; x < state.range(0); ++x) {
      benchmark::DoNotOptimize(x);
    }
  }
}

BENCHMARK(BM_spin_empty)
  ->ComputeStatistics("ratio", [](const std::vector<double>& v) -> double {
    return std::begin(v) / std::end(v);
  }, benchmark::StatisticUnit::kPercentage)
  ->Arg(512);
```

## 内存使用情况

在评估 CPU 性能的同时，跟踪基准测试的内存使用情况也经常很有用。因此，benchmark 提供了 `RegisterMemoryManager` 方法，允许注入自定义的 `MemoryManager`。

如果设置了 `MemoryManager`，则会在基准测试运行开始和结束时调用 `MemoryManager::Start` 和 `MemoryManager::Stop` 方法，允许用户代码填写有关分配次数、使用的字节数等信息的报告。

然后，这些数据将与其他性能数据一起报告，目前仅在使用 JSON 输出时支持。

## 使用 RegisterBenchmark(name, fn, args...)

`RegisterBenchmark(name, func, args...)` 函数提供了一种创建和注册基准测试的替代方法。`RegisterBenchmark(name, func, args...)` 创建、注册并返回一个指向新基准测试的指针，该基准测试具有指定的名称，并调用 `func(st, args...)`，其中 `st` 是一个 `benchmark::State` 对象。

与只能在全局范围内使用的 `BENCHMARK` 注册宏不同，`RegisterBenchmark` 可以随时调用。这允许通过编程方式注册基准测试。

此外，`RegisterBenchmark` 还允许将任何可调用对象注册为基准测试。这包括捕获的 lambda 函数和函数对象。

例如：

```c++
auto BM_test = [](benchmark::State& st, auto Inputs) { /* ... */ };

int main(int argc, char** argv) {
  for (auto& test_input : { /* ... */ })
      benchmark::RegisterBenchmark(test_input.name(), BM_test, test_input);
  benchmark::Initialize(&argc, argv);
  benchmark::RunSpecifiedBenchmarks();
  benchmark::Shutdown();
}
```

## 以错误退出

当基准测试中发生由外部因素（例如文件 I/O 和网络通信）引起的错误时，可以使用 `State::SkipWithError(const std::string& msg)` 函数跳过该次基准测试运行并报告错误。请注意，只会跳过 `KeepRunning()` 的未来迭代。对于基准测试循环的 range-for 版本，用户必须显式退出循环，否则将执行所有迭代。用户可以显式返回以立即退出基准测试。

`SkipWithError(...)` 函数可以在基准测试中的任何位置使用，包括基准测试循环之前和之后。此外，如果已经使用了 `SkipWithError(...)`，则不需要到达基准测试循环，并且可以提前从基准测试函数返回。

例如：

```c++
static void BM_test(benchmark::State& state) {
  auto resource = GetResource();
  if (!resource.good()) {
    state.SkipWithError("Resource is not good!");
    // KeepRunning() loop will not be entered.
  }
  while (state.KeepRunning()) {
    auto data = resource.read_data();
    if (!resource.good()) {
      state.SkipWithError("Failed to read data!");
      break; // Needed to skip the rest of the iteration.
    }
    do_stuff(data);
  }
}

static void BM_test_ranged_fo(benchmark::State & state) {
  auto resource = GetResource();
  if (!resource.good()) {
    state.SkipWithError("Resource is not good!");
    return; // Early return is allowed when SkipWithError() has been used.
  }
  for (auto _ : state) {
    auto data = resource.read_data();
    if (!resource.good()) {
      state.SkipWithError("Failed to read data!");
      break; // REQUIRED to prevent all further iterations.
    }
    do_stuff(data);
  }
}
```

## 更快的 KeepRunning 循环

在 C++11 模式下，应优先使用 ranged-based 的 for 循环来运行基准测试，而不是  `KeepRunning` 循环。例如：

```c++
static void BM_Fast(benchmark::State &state) {
  for (auto _ : state) {
    FastOperation();
  }
}
BENCHMARK(BM_Fast);
```

ranged-for 循环比使用 `KeepRunning` 更快的原因是因为 `KeepRunning` 它需要内存加载并存储每次迭代的迭代计数，而 ranged-for 变体能够将迭代计数保存在寄存器中。

例如，使用 ranged-for 的 for 方法的空内循环如下所示：

```assembly
# Loop Init
  mov rbx, qword ptr [r14 + 104]
  call benchmark::State::StartKeepRunning()
  test rbx, rbx
  je .LoopEnd
.LoopHeader: # =>This Inner Loop Header: Depth=1
  add rbx, -1
  jne .LoopHeader
.LoopEnd:
```

空 `KeepRunning` 循环它看起来像：

```assembly
.LoopHeader: # in Loop: Header=BB0_3 Depth=1
  cmp byte ptr [rbx], 1
  jne .LoopInit
.LoopBody: # =>This Inner Loop Header: Depth=1
  mov rax, qword ptr [rbx + 8]
  lea rcx, [rax + 1]
  mov qword ptr [rbx + 8], rcx
  cmp rax, qword ptr [rbx + 104]
  jb .LoopHeader
  jmp .LoopEnd
.LoopInit:
  mov rdi, rbx
  call benchmark::State::StartKeepRunning()
  jmp .LoopBody
.LoopEnd:
```

除非需要兼容 C++03，否则应优先使用 ranged-for 变体来编写基准循环。
